2026-09-02 — Audit follow-up: anima's own cache identity, and two tests that could not fail

Request. Same session as the entry below, second pass: close the findings that were classed as pre-existing or as test-quality rather than as defects, so nothing from the audit is left open.

anima shared text embeddings between different LLMs. The audit filed this as pre-existing and out of scope, which it is, but it is the same silent-reuse class as the text cache fix below and it had a free fix. text_encoder_cache_key returns '' for anima deliberately — putting the key in the fingerprint would move the cache path of every existing anima install. The side effect was that nothing distinguished two anima runs with different llm_path, so one run silently reused the other's embeddings.

The fix separates the two questions the one string was answering. The fingerprint decides whether to rebuild, so adding to it is expensive; the manifest only records whose contents these are, and a cache with no manifest is already treated as compatible. So BasePipeline gains text_encoder_identity, defaulting to the fingerprint key so every other model is unchanged, and cosmos_predict2 overrides it to name the LLM for anima as well as anima_refiner. No existing cache moves and none is invalidated; new ones make a claim that a later mismatch can be caught against. This is the same recorded-not-fingerprinted shape vae_cache_key already uses for latents.

Two tests asserted text that could not fail. The audit's most useful test finding was not a missing test but a passing one: a test that would still pass if the behaviour it covers were inverted.

  • test_ddp_no_sync_wraps_all_but_the_last_micro_batch asserted that two string literals appear somewhere in distill_refiner.py. Inverting the condition to not is_last leaves both literals intact, so the test could not tell the accumulation boundary from its opposite — while the equivalent ZeRO logic next to it is exercised against a real engine. Added TestNoSyncBoundaryBehaviour, which runs micro_batch_context and checks which context comes back, including that world size 1 never touches no_sync (it only exists on a DDP-wrapped module).
  • test_the_two_prefix_lists_agree checked only that the pipeline's prefixes are a subset of _CHECKPOINT_PREFIXES. The other direction is the mirrored bug: a prefix the extractor knows and the pipeline does not means a file that loads as context_refiner_path fails as transformer_path. Both directions are now asserted, plus that the regex still matches anything at all — a regex that silently stops matching turns this into a test of nothing.

The prefix check passed in the new direction immediately, so the lists did agree; the point is that nothing was checking.

Not changed. The remaining TestScriptStructure cases still assert on source text. That is the right tool for some of them — "the launcher sets this env var", "this import exists" — and rewriting them wholesale was not worth the churn. The two fixed here are the ones where a real behaviour with a real inversion sat behind the string.

2026-09-02 — Five-agent adversarial audit: a stale text cache, an unguarded teacher, and a drift-guard hole

Request. A full adversarial audit of the branch against baseline fd00a5e, then fix everything it found. Four specialists covered architecture, objective mathematics, distributed/numerical behaviour, and tests/cache/upstream; the two headline findings were re-verified at source level before anything was changed.

What the audit did not find is worth stating first. Every distillation objective held up. The CFG formula is algebraically the textbook one, the rollout timestep schedule and Euler sign are identical across the trainer, models/cosmos_predict2.py and the sampler, the rollout is teacher-driven and fully inside no_grad with gradient reaching only the refiner, ContextRefiner.init_weights covers all 28 parameters on all four construction paths, and the ZeRO accumulation boundary is correct against DeepSpeed 0.18.4's own source. The relational loss's deviation from textbook RKD was re-derived and is provably the right call: per-side normalisation cancels a uniform collapse factor exactly, so the textbook form cannot see the failure it is meant to price.

The text embedding cache could serve embeddings for captions that no longer exist. keep_text_embedding_cache was new on this branch, undocumented, and mapped straight onto keep_on_fingerprint_change. It was added to mirror keep_latent_cache, but the two are not symmetric. Captions were deliberately removed from the latent fingerprint, so that flag has almost nothing left to suppress. For the text cache the caption text is essentially the whole fingerprint — so the flag's only reachable effect was to ignore an edit to the captions and pair old embeddings with new text by index, with correct shapes, a correct count, and no error. That contradicts the contract the introducing commit wrote down for itself: keep_* means "do not recache unnecessarily", and a caption edit is a necessary recache.

Fixed by recording a digest of the input in the cache manifest beside the producer identity — identity answers "who produced this", content_digest answers "from what". On reuse, the first N current captions are re-hashed against it. Appending rows still reuses what is cached, which is the case the flag exists for and the reason it was kept rather than deleted; editing a row that is already cached rebuilds. A cache with no recorded digest claims nothing and is still reused, so existing installs are unaffected. The manifest is now schema 2, and both fields are optional in it.

The teacher had no guard for the fully-masked row the student got one for. ContextRefiner.forward widens an all-padding attention mask so the row attends freely, because the fused CUDA backends can return NaN for a fully-masked softmax and NaN times zero is still NaN. LLMAdapter — the teacher the refiner is distilled against — had no such guard, and build_unconditional_features hands it an all-zero source_attention_mask on every guided-rollout micro-batch. The docstring explaining why the teacher "needs no help" is about target_attention_mask, the T5 query sequence; source_attention_mask is a different mask and is genuinely all zero for an empty caption. The root is pre-existing and reaches plain anima too; what is new is that the rollout exercises it every step rather than on unlucky caption-dropout draws.

The guard moved into Attention itself as allow_fully_masked_rows, so both consumers get it from one place — the duplication is what let them drift apart. This is provably not a behaviour change for anima: _compute_text_embeddings zeroes every masked position, and k_proj/v_proj carry no bias, so the values are zero and attending freely returns the same exact 0.0 the masked softmax was meant to produce. That is asserted directly in the new tests rather than argued.

The drift guard did not cover the newest dependency surface. tools/check_vendored_apis.py covered torch and bitsandbytes; check_comfy_signatures.py covered ComfyUI. Neither covered the transformers/accelerate surface this branch added, which walks concrete attribute paths (full_model.model.language_model) and indexes the hidden-states tuple by position — and requirements.txt pins neither. Added both, with two behavioural checks an import test could not make: that output_hidden_states still yields num_hidden_layers + 1 tensors ending in last_hidden_state, and that init_empty_weights still leaves buffers off the meta device. Checks went from 34 to 60.

The accelerate check found something on its first run. It was written to assert include_buffers defaults to False. It does not: the default is None, resolved from the ACCELERATE_INIT_INCLUDE_BUFFERS environment variable. The effective default is still False, so nothing is broken, but the property ContextRefiner.init_weights relies on — that inv_freq stays real while every parameter goes to meta — is environment-controlled rather than fixed. The check was rewritten to prove it by construction instead of by reading a signature.

Smaller fixes. DDP resume now records batch_size, grad_accum, world_size and precision and warns when they drift, rather than only refusing under ZeRO — a deliberate warn rather than a refusal, since DDP replicates optimizer state and resizing is legitimate; what does not carry across is the alignment of the saved step and the schedule total. The DDP fp16-mixed path no longer advances the LR scheduler on a step GradScaler skipped, which DeepSpeed already gated on and this did not. Caption files are read as utf-8-sig: a Windows editor's BOM survives str.strip(), so it rode into the tokenizer on the first caption of a file and nowhere else. Files this repo writes itself keep plain utf-8.

Documentation. keep_text_embedding_cache is now documented in examples/dataset.toml, including what it is not for. The design note claiming the denoising rollout was unimplemented was written before the rollout landed and now points at it. A comment in utils/saver.py warned of a step/global_step prefix collision that startswith cannot produce; a local named missing held the keys that were present. Both corrected.

Left deliberately unfixed. Nothing found requires a redesign, and no defect reachable from a shipped example config silently corrupts a default run. What remains is that nothing on this branch has ever executed on a GPU. Three experiments should run before serious compute: one GPU with rollout.guidance_scale > 0 asserting a finite loss (this settles the teacher-mask finding, which cannot be reproduced on CPU because the CPU math backend returns zeros where the fused kernels return NaN); two GPUs at gradient_accumulation_steps=3 confirming three real optimizer updates in nine steps; and one distil-save-sample round trip, because no image has been produced from this branch.

2026-09-01 — The 4-GPU configs move to a caption corpus

Request. This phase does not use a dataset.toml. Point the two 4-GPU configs at a JSONL corpus and restate the caption settings under [distill].

The switch itself is two keys. What it changes is where caption augmentation comes from: with a dataset.toml, caption_augment_config falls back to the dataset’s own settings, so distillation augments the way the diffusion stages do without restating anything. A corpus carries no dataset config, so every unstated setting silently defaults to off — and the refiner then learns a caption distribution the diffusion stages never see. The script already warns about this; the configs now restate prefix_tag_caption, shuffle_tags, cache_shuffle_delimiter and tag_dropout_rate so the warning does not fire and the behaviour is visible in the file.

The table guard had a blind spot exactly the size of this change. Adding those four keys made test_every_key_is_read_from_the_table_it_sits_in fail, claiming the script never reads them — while a direct call to caption_augment_config on the same file resolved all four correctly. The extractor recognises config[table].get(key) and friends, but caption_augment_config reads through a closure, setting(key, default), which indexes the table with a variable. So the whole caption-augmentation family was invisible, and the guard’s first act on meeting them was a false alarm on the documented way to configure a corpus run. The extractor now understands setting(), and test_the_extractor_finds_the_known_reads pins one of those keys so the extension cannot rot silently.

  • A warmup that is fine at 20,000 steps is not fine at 1,300. The global batch here is 48 x 8 x 4 = 1536, so an epoch is len(captions) / 1536 steps and the run is twenty of those. At 100,000 captions that is 1,300 optimizer steps, where the default warmup_steps = 500 is 38% of the schedule — nothing errors, the run just spends a third of itself ramping. warmup_advice() now says so at startup and names the number it would use, and both configs carry the arithmetic as a table. Extracted rather than left inline in main(), for the same reason resolve_schedule was: a thing that only runs inside a 500-line function is a thing that only gets tested by running a 500-line function.
  • A documentation ambiguity worth naming. denoising-rollout.md said adjacent trajectory points give correlated signal, “the same argument [probe] num_blocks rests on”. That reads as though the probe’s block count affects the rollout. It does not: num_blocks selects which frozen cross-attention blocks objective 1 measures through, and the rollout calls the whole DiT because it needs the velocity the model actually predicts. Said explicitly now.

2026-09-01 — Six defects in the epochs and checkpoint-retention round

Context. The previous entry shipped epochs, retention, tagged checkpoints and resume, and recorded that the tests arrived a commit late. An audit of that work found six real defects, two of them blockers on the exact configuration a four-GPU box would run. Two were found by reading the code here, four by an independent adversarial reviewer given the same brief. All six are fixed below.

The two blockers were both in code written the day before, and both had been reported as verified. That is the finding worth keeping. “Verified” had meant a throwaway script exercising the happy path of one function; neither blocker is visible from that vantage point, because both are about the order in which a 500-line main() reads its own variables and about what a library does to an object it is handed. Neither is reachable without either running the real thing or reading the whole function as a sequence.

1. The step count was read before it was known (blocker)

With [distill] epochs set, steps stays None until it is derived from the sampler. The sampler was built below the optimizer, so build_lr_scheduler received total_steps=None. CosineAnnealingLR(T_max=None) constructs without complaint and SequentialLR hands over to it at the warmup milestone, so the failure is a TypeError from inside torch at scheduler step 500 — roughly 500 optimizer steps at a global batch of 1536, with a traceback pointing nowhere near the config. Both shipped four-GPU configs use epochs = 20 with the default warmup_steps = 500, so both died. Setting resume_from on an epochs config raised TypeError at startup instead, from the resume guard comparing an int against None.

Fixed structurally rather than by moving two lines. The sampler and the step count are one decision, so resolve_schedule() now returns both together and is called immediately after the captions load. Reading one without the other is no longer possible to express. It also means the “too few captions” refusal fires before ~7 GB of teacher and student weights are resident, which is what validate_config_early exists to achieve. A warning was added for warmup_steps >= steps: with epochs the step count is derived rather than written down, so a warmup longer than the whole run is easy to arrive at without noticing, and it silently disables the decay phase.

2. ZeRO wrote optimizer state it could not read back (blocker)

deepspeed.initialize mutates the client optimizer in place: stage_1_and_2.py:473 replaces each param group's parameter list with a single flat rank-local fp32 partition. So under zero1/zero2, rank 0's state_dict() is a shard, not the state, and the other ranks' shards were never written at all. Three failure modes, all reproduced against the installed torch and deepspeed: the file is written without error; resuming it raises “loaded state dict contains a parameter group that does not match the size of optimizer's group”; and resuming a DDP-written file under ZeRO loads successfully, then has its state orphaned by initialize and blows up with a KeyError in Optimizer.state_dict at the next save — hours later.

Every rank now writes distill_state_<tag>_rank<N>.pt, and the load moved to after build_strategy so the optimizer has the shape the shard was written in. DDP could load on either side of the wrap; it moved too, so there is one order to reason about and so the fp16 GradScaler exists to be restored as well. The two layouts are named apart on disk, which is what stops a DDP file from being fed to a sharded optimizer, and world_size is recorded so a resume into a differently sized job is refused rather than loading another rank's partition.

This fix is unit-tested but not hardware-tested. deepspeed.initialize does not run on this machine — it JIT-builds deepspeed_shm_comm and needs MSVC. The file-level behaviour is covered in the suite against a plain torch optimizer; the premise it rests on was confirmed by reading the installed deepspeed source, not by running it. tools/test_zero_resume_gpu.py checks all five claims on a real two-rank GPU box and should be run before anyone trusts ZeRO resume. The default and the shipped configs are ddp, which is fully covered.

3. A commented key in the wrong table (serious)

Both four-GPU configs put #resume_from under [distill]; the code reads it from [student]. Uncommenting it starts from a randomly initialised refiner at step 0, silently, and the fresh run's checkpoints then overwrite the interrupted one's. The existing guard, test_every_key_is_read_from_the_table_it_sits_in, is exactly the right shape for this bug class and cannot see it: toml.load discards comments. A companion test now scans commented #key = lines, following commented table headers so that the fully commented #[rollout] block in distill.toml does not read as a hundred misplacements. It was checked against the buggy version of the config before being kept, so it is known not to pass vacuously. This repo has now shipped a key in the wrong table three times.

4. A tagged full model found the wrong state file (serious)

training_state_path matched only the context_refiner stem, so model_epoch7.safetensors — documented as a first-class rollback target — resolved to the untagged distill_state.pt: epoch-7 weights paired with the newest moments and the newest step counter. That is precisely the mispairing the function's own docstring says it exists to prevent. It now matches both prefixes a save writes.

5. Retention could delete the checkpoint it had just written (minor)

Tags are ordered by their number, which only increases within one uninterrupted run. Reusing an output_dir, or resuming onto fewer ranks (which raises steps_per_epoch and lowers the epoch number), writes a lower tag than what is already there — and the prune then removed the fresh checkpoint, announcing it as a routine eviction. The current tag is now protected. Rank shards are pruned with their tag as well, globbed on the _rank separator rather than on the number: a bare distill_state_epoch1* also matches distill_state_epoch10.pt.

6. A resume correlated the augmentation noise across ranks (minor)

main() offsets the global random seed by rank so the ranks draw different caption augmentations. Only rank 0 writes a DDP state file, and restoring it on every rank collapsed that offset for the rest of the run. The captions still differ — EpochSampler shards them — so this was correlation in the noise, not duplicated training data. The stream is now restored only by the rank that owns it; the others re-offset. The torch stream is rank-uniform by construction and is still restored everywhere, which is what an uninterrupted run would have had.

  • Also carried in resume state now: the rollout's two RNG streams (seeded apart from the global one so that enabling the rollout does not shift the caption augmentation), and the fp16 GradScaler. And the restored learning rate is pushed into the optimizer immediately: load_state_dict restores the schedule's position but leaves the optimizer on its construction-time LR until the next step(), which is one step near zero at the start of a warmup.
  • Verified correct under audit, worth recording because it was doubted: mid-epoch resume walks the right caption stream. The offset derives from the absolute step and epoch_order is a pure function of (seed, epoch), so position is reconstructed rather than remembered. Also: 8-bit optimizer state survives the round trip — bitsandbytes overrides load_state_dict with a uint8 guard, so torch's dtype-casting policy does not corrupt the quantisation blocks under bf16-full, which is the pairing the four-GPU config ships.
  • Documentation. The README claimed “checkpointing is unaffected either way” under ZeRO. True when checkpointing was weights-only; optimizer state is exactly what ZeRO shards.

2026-09-01 — Epochs for distillation, and checkpoint retention for both trainers

Request. Describe a distillation run in epochs the way the rest of the repo does, keep only the last N checkpoints, and produce ready-to-run 4-GPU configs with and without the rollout.

I got the first one wrong before getting it right. Asked for “20 epochs”, I reported that the distillation script has no epoch concept and asked how many captions there were so I could convert to steps. That was accurate about the code and useless as an answer: the request was to add epochs, not to work around their absence. Worth recording, because the failure mode is subtle — a true statement about the current state delivered instead of the work.

What an epoch had to mean. The loop drew random.sample(captions, batch_size) per micro batch, which samples with replacement across steps: some captions appear many times before others appear once. EpochSampler shuffles the full list with a seed derived from the epoch number — identical on every rank — and then takes this rank's stride. Shuffling before sharding is the part that matters: sharding a fixed order would pin each rank to the same captions for the whole run. Verified with four ranks that the shards do not overlap, together cover every usable caption, are equal sized, differ between epochs, and are deterministic.

That determinism is why resuming mid-epoch stores nothing about position: the order is a pure function of (seed, epoch), so the resumed run lands on the right captions by construction. It is a better property than a saved dataloader cursor, not a missing one.

keep_last_n_checkpoints is the only feature here that deletes data the user did not ask it to delete, so its edges are pinned by tests rather than by care. Counted separately per kind — epoch<N>/, step<N>/ and global_step<N>/ in train.py — because the three are produced by different triggers at different rates and pruning them as one pool would let a fast trigger evict a slow one. The newest of each is never removed: DeepSpeed's latest file names the global_step it will resume from, and pruning that one turns a cache into an unrecoverable run. Ordered by the number in the name, not lexicographically (step9 must not outlive step100) and not by mtime, because a resumed run rewrites older directories' timestamps.

Distillation had nothing to keep N of. It overwrote a single context_refiner.safetensors. It now writes a tagged set per save and copies it to the untagged names, so every config pointing at the stable name keeps working and gets the newest. training_state_path derives from the weights filename rather than being fixed, so a tagged checkpoint carries its own optimizer state — resuming from an older tag would otherwise pair the newest moments with older weights. save_full_model moved from once-at-the-end to once-per-checkpoint for the same reason: the point of keeping N checkpoints is being able to go back to one, and a refiner without the model it belongs in is half a checkpoint.

Resume was missing a piece. It restored the optimizer, the scheduler and the step counter, but not the RNG — and caption shuffling and tag_dropout_rate pull from the global random stream, so a resumed run saw different augmentations than an uninterrupted one would have. Both the Python and torch states are saved now, and a checkpoint written before this still resumes; it simply cannot reproduce the augmentation.

The tests came a commit late, which is the thing to avoid next time. All four features above shipped verified by throwaway scripts and with nothing in the suite, then were covered in the following commit. This branch has already been burned twice by exactly that gap — 182 tests passing while every training run was broken, and a step-0 NameError surviving because the tests matched source text instead of importing the module. Verified is not covered.

  • Two ready-to-run 4-GPU configs. examples/anima_refiner/distill_4gpu.toml and distill_rollout_4gpu.toml differ only in the [rollout] table, so the two runs are comparable: 20 epochs, a global batch of 1536 (48 × 8 × 4), bf16-full with AdamW8bitKahan at 5e-5, save_every_n_epochs = 1, keep_last_n_checkpoints = 3, log_every = 5. The rollout one carries an ordered list of what to reduce first if it runs out of memory.
  • A documentation gap that was purely conversational. The comparison of the four distillation objectives — what each can and cannot see, and what each costs — existed only in chat. docs/anima_refiner/distillation-methods.md records it, including that the pooled term is nearly useless at the shipped settings, with the measurements that say so.

2026-09-01 — Denoising rollout, and cache reuse that depends on compatibility

Request. Two things, both settled by design review before any code was written: make cache reuse depend on whether the cache is actually compatible rather than on a flag, and add the denoising rollout objective from the CVPR 2025 text-encoder distillation paper as an optional distillation mode.

The research changed the design. "Rollout" usually implies a student rolling out its own predictions, which brings exposure bias and error accumulation with it. Algorithm 1 of Scaling Down Text Encoders of Text-to-Image Diffusion Models does not do that. The trajectory is advanced by the teacher, both models are evaluated at the same x_t, and the student never sees its own output as input. None of the exposure-bias literature applies, and the whole walk can therefore run under no_grad — which is what makes steps an inference cost and loss_points a backward cost, independent of each other.

One adaptation was required, and it is the part most likely to be wrong. The paper is written for DDPM; Anima is rectified flow. Its DiT predicts a velocity and its training target is noise - x0 with x_t = (1-t)*x0 + t*noise, so dx/dt = v exactly and the DDPM posterior update does not carry over. Verified numerically rather than reasoned about: with an exact velocity the Euler step x ← x - (t - t')*v lands on the true x_t' to 2.4e-07, a full walk from t=1 lands on x0 to 4.2e-07, and the opposite sign is off by 1.61.

Why a rollout rather than random noisy latents. This stage has no images, so there is no x0 and no way to build x_t = (1-t)*x0 + t*noise the way training normally would. The trajectory is the only source of x_t that lie where the model will actually be asked to predict. That, rather than fidelity to the paper, is the justification.

Decision: off by default, and off means off. Enabling it keeps the DiT resident — roughly 3.5-4 GB in bf16 for Anima, taking this stage from about 6 GB to 10-12 GB. The ~6 GB figure is what makes distillation runnable on modest hardware, so at loss_weight = 0 build_teacher still throws the DiT away and nothing is allocated. A test asserts that discard path is still there.

Measured before choosing a default. Forward plus backward on a reduced-scale replica at 1 / 2 / 4 / 8 loss points: 26 / 49 / 97 / 197 ms, linear as expected, with the 8-step trajectory a fixed 78 ms — about three loss points' worth. Adjacent trajectory points give correlated signal, which is the same argument [probe] num_blocks rests on, so the default is 2.

Classifier-free guidance is configurable rather than assumed. Above 0 it evaluates the unconditional branch on both sides, doubling the DiT forwards. It is worth having because that branch is fed by an empty caption, which is exactly where the refiner path diverges most from the T5-native DiT — the same divergence an earlier commit fixed in _tokenize. The student's unconditional features are recomputed with gradient every step, because they depend on the refiner too.

Cache compatibility: recorded, not fingerprinted. keep_latent_cache had shipped as a hard override that reused the cache whenever the fingerprint moved, with no idea whether the contents still belonged to this model. It now means "do not recache unnecessarily", and an incompatible cache is rebuilt regardless — reusing latents produced by a different VAE is training on silently wrong data, and no flag should ask for that.

Compatibility lives in a cache_manifest.json beside each cache rather than in the fingerprint. Folding it into the fingerprint would be simpler and would rebuild every existing cache once; recording it costs existing installs nothing, because a cache with no manifest predates the check and is treated as compatible.

There is no config key that names the VAE across models. It is vae_path for seven of them, diffusers_path for seven, ckpt_path for two, checkpoint_path for one, and vae / audio_vae elsewhere. A generic "any key naming a file" rule is wrong in the other direction: transformer_path names a file that affects neither latents nor text embeddings, so including it would rebuild the cache on every DiT change — exactly what anima and anima_refiner sharing a cache tree exists to avoid. So identity is declared per model through vae_config_keys, empty by default, filled in for 15 models. Empty means no identity is recorded and every existing cache stays valid.

keep_text_embedding_cache did not exist before this. An earlier commit had grown a keep_on_fingerprint_change parameter on _cache_text_embeddings with no config key wired to it — a dead argument. Relatedly, text_encoder_cache_key was implemented by exactly one model out of 23 and every other model fell through a lambda returning ''. Things the maintainer needs to know

  • The three precision axes are one object, not three settings.   • Precision is applied before the optimizer is constructed. AdamW sizes exp_avg and exp_avg_sq to each parameter’s dtype at construction, so casting afterwards leaves the optimizer holding state of the wrong dtype. There is a test asserting exp_avg comes out bf16 under bf16-full.

2026-08-31 — Caption corpus, tag dropout, multiline .txt captions

Request. A script that flattens every caption in a dataset.toml into one file, so distillation can be pointed at that file instead of the dataset. Plus tag dropout, and multi-line .txt sidecars.

A premise worth correcting first

The request was framed as recovering captions the pipeline drops: "if an image has multiple captions, the current flow only picks one." It does not. SizeBucketDataset.cache_latents expands every caption of every image into its own entry in iteration_order — an image with three captions is three training samples, and enumerate_captions already extended the whole list. With captions.json, nothing was ever being lost.

What is lost is narrower and real: a .txt sidecar is read as [f.read().strip()], so a file with three lines is one caption containing two newlines. That is the only place captions actually go missing.

So the corpus tool's value is not "recover dropped captions" — it is that distillation trains only the text frontend, and pointing it at a dataset.toml makes it walk every media file and open every tar purely to discover which captions exist. At three million images that is worth doing once. The corpus is a cache of that walk, not a second source of truth. Worth saying plainly, because a tool built on a wrong premise gets used for the wrong thing.

Decisions

  • The corpus is faithful, not preprocessed. Captions are written exactly as the dataset holds them, tag marker included, shuffling not baked in. One corpus then serves runs configured differently, and every epoch can draw a fresh variant. caption_prefix is the one exception — a fixed string with no random component, so it is applied at export.
  • Marker stripped at train time, not at export. Stripping it at export would be cleaner-looking and would destroy the only signal saying which captions are tag lists. A plain .txt corpus has nowhere to put a replacement flag, so that choice would have quietly made the tag/prose distinction unrepresentable in one of the three formats.
  • Dropout never empties a caption. An all-dropped caption is the empty string, which is the unconditional embedding — the trainer already mints those deliberately at UNCOND_FRACTION. Silently producing more would shift the conditioning ratio with no config change to explain it. With two tags at rate 0.5 that is a 1-in-4 event, not a corner case. At least one tag always survives.
  • multiline_captions is opt-in. Turning it on changes how many training samples every existing dataset with wrapped .txt files produces. That is a silent retraining-scope change for models unrelated to this branch, so it defaults off and needs --regenerate_cache, matching how cache_shuffle_num already behaves.
  • Distillation augments per sample; the diffusion stages cannot. The diffusion stages bake cache_shuffle_num variants into the embedding cache, because the embedding is computed once. Distillation re-embeds every step, so freezing a fixed variant set there would be a pure loss. It reads its settings from the dataset.toml's top level when that is the source, so a run matches the diffusion stages without restating them — top-level keys only, since a flat batch of captions has no directory to attach an override to.
  • Case-insensitive marker matching, requested mid-implementation. A marker is a hand-written annotation spread over millions of files; "Special:", "special:" and "SPECIAL: " have to mean the same thing. Only the first len(marker) characters are casefolded — this runs per sample and captions are long. The body is stripped afterwards, so "SPECIAL: a, b" does not train as " a, b" and tokenize differently from its neighbours for no reason.

2026-08-30 — Anima Refiner: replacing Anima's LLMAdapter text frontend

Request. Add an architecture that swaps Anima's LLMAdapter for the cap_embedder + bidirectional refiner blocks that Lumina 2 and Z-Image use, so any Transformers LLM (target: Qwen3.5-2B-Base) can drive the DiT. New model type anima_refiner; cosmos_predict2 and anima must be untouched.

Why the adapter exists at all

Worth recording, because it explains the whole design. In ComfyUI Anima is literally class Anima(MiniTrainDIT) — a Cosmos-Predict2 DiT whose only addition is the adapter. Cosmos-Predict2 feeds old-T5 encoder output straight into cross-attention with no adapter, so the adapter is a retrofit letting a Qwen3 LLM drive a T5-native DiT.

The mismatch it papers over is not dimensional: old T5-XXL has d_model = 1024 and Qwen3-0.6B has hidden_size = 1024. They already agree. A six-layer cross-attention module with a 32128-entry embedding table was built anyway, which is the evidence that the gap is representational — bidirectional encoder vs causal decoder, span corruption vs next-token, sentencepiece vs BPE.

Findings that changed the design

FindingConsequence
Qwen3.5 interleaves linear and full attention (full_attention_interval = 4), full-attention layers at 3/7/11/15/19/23 hidden_states[-2], Lumina 2's convention, lands after a linear-attention layer. Default is -1 here.
Linear-attention layers are recurrences with no attention matrix They cannot be made bidirectional by flipping a mask, so the refiner's bidirectional blocks are load-bearing, not decoration.
Qwen3.5-2B and Qwen3.5-2B-Base have byte-identical config.json No architecture change needed for Base; only the tokenizer differs (eos <|endoftext|> vs <|im_end|>). Verified by fetching both.
Teacher and student features are indexed by different tokenizers A position-wise distillation MSE runs without error while comparing unrelated slots. The loss is measured at the cross-attention output instead, which is a weighted sum over text positions and therefore invariant to indexing.

Mistakes made in the first version, and what fixed them

Recorded honestly, because four of them were regressions in code shared with other models.

Shape derived from config instead of from the weights. load_diffusion_model loads with if name not in state_dict: continue, so a checkpoint holding more refiner layers than n_refiner_layers asked for silently lost the surplus. Measured: a 4-layer refiner loaded under the default of 6 dropped 24 tensors with no warning. Now the layer count and input dimension come from the weights, and a config that contradicts them raises.

cache_name discarded the VAE latents. A config key was added to invalidate stale text embeddings when the text encoder changed. It worked by changing the pipeline's name, which is the root of the whole cache tree — so switching text encoder also threw away latents, by far the more expensive half, for a component that had not changed. Replaced by a text-encoder identity mixed into the text embedding fingerprint only. anima_refiner now also shares anima's cache directory deliberately, so latents cached by an anima run are reused as is.

Three smaller leaks into shared code, all now gated on the model type: base_lr and max_text_length were read unconditionally, giving anima and cosmos_predict2 config keys nobody asked for; and the vision-language branch of the llm_path directory loader changed how anima would load a VLM.

One near-miss caught during implementation rather than after: the text-encoder identity was first appended to new_fingerprint_args unconditionally. Hasher.hash([i]) and Hasher.hash([i, '']) differ, so that would have invalidated the text embedding cache of every model in the repo. Extra fingerprint args are now only appended when non-empty, and the old fingerprint was verified byte-for-byte.

Decisions made that were not in the request

  • OPLoRA excludes the refiner. OPLoRA projects a low-rank update away from the top-k singular subspace of the pretrained base weight. A newly built refiner has no pretrained weights to protect, and two of its six Linear layers per block are zero-initialised — where, as measured, the SVD does not fail or produce NaN but returns an arbitrary orthonormal basis. Projecting against that costs the adapter rank directions for nothing. Implemented as a per-model oplora_exclude_names, empty everywhere else.
  • Distillation reads dataset.toml. It originally took a bespoke caption format while every other mode used the repo's. Now it goes through utils.dataset.enumerate_captions(), which mirrors DirectoryDataset's resolution rules exactly. Images are enumerated to find their captions but never opened.
  • context_refiner_path wins over the checkpoint, loudly. Both orderings are defensible; silence is not, so it warns naming both files every time.
  • Stage numbering removed. stage1/stage2 implied a pipeline the code does not enforce — every mode loads identically and can run in any order. The configs are named for what they train instead.
